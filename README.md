## 질문 키워드로 규정 파일 선택

`app/gemini_client.py`의 `REGULATION_KEYWORDS`는 파일명과 질문 키워드를 연결한다.
`select_regulation_files()`가 질문에서 일치하는 파일을 고르고,
`load_regulations()`가 `data/regulations/`에서 그 파일들만 `open()`으로 읽는다.
`build_system_prompt()`는 선택한 본문을 `[참고 규정]`에 넣는다.

| 질문 | 선택하는 파일 |
| --- | --- |
| 월급은 언제 들어오나요? | 급여규정.md |
| 자기 계발비 얼마까지 지원되나요? | 복리후생규정.md |
| VPN 설치 방법은? | 정보보안_IT이용규정.md |
| 배우자 출산휴가와 경조사비는? | 휴가_근태규정.md, 복리후생규정.md |
| 쉽게 설명해줘 | 최근 사용자 질문의 규정(명확한 후속 질문일 때) |
| 자기계발비 질문 후 '영수증은 언제까지?' | 복리후생규정.md (출장 규정으로 바꾸지 않음) |
| 새 대화에서 '영수증은 언제까지?' | 선택 없음, 비용 종류 확인 |

- 구체적인 새 주제의 키워드가 있으면 현재 질문을 우선한다. 과거의 모든 규정을 합치지 않는다.
- `COMMON_KEYWORDS`의 영수증·증빙은 여러 제도의 공통 단어다. 이전 주제를 확인하고,
  주제가 없으면 `AMBIGUOUS_KEYWORDS`를 기준으로 필요한 비용 종류를 묻는다.
- 키워드가 없으면 파일을 읽지 않는다. 업무 규정 질문이면 분야를 확인하도록 지시한다.
  키워드 미일치는 규정 부재가 확정된 것이 아니다.
- 선택한 문서에 제도가 없으면 `규정에는 없는 내용입니다.`라고 안내한다.
  일부 조건만 있는 경우에는 있는 기준과 미기재 사항, 문서의 문의처를 구분한다.
- 키워드는 공백·구분자·영문 대소문자를 정리해 비교한다. 동의어·새 파일은
  `REGULATION_KEYWORDS`에 직접 추가해야 한다. 모든 표현을 자동으로 이해하는 검색은 아니다.
- 선택한 MD는 매 질문마다 읽으므로 UTF-8로 저장한 변경이 다음 질문에 반영된다.
- 전송할 때 검색 키워드 목록과 항목 식별 코드만 제거한다. 규정 본문과 원본 파일은 유지한다.
- 선택한 파일 누락·빈 파일·읽기 오류는 메시지 저장과 Gemini 호출 전에 HTTP 503으로 처리한다.
- 전체 MD를 보내던 경우보다 규정 본문 입력량이 줄어든다. 지침·질문·최근 대화는 계속 전달되므로
  실제 총 토큰 절감량은 선택 파일과 대화 길이에 따라 달라진다.

기존 `POST /conversations/{conversation_id}/chat`, Gemini `system_instruction`,
Supabase 저장, Redis 대화 이력, 프런트엔드 SSE 표시 구조를 사용한다.

## 답변 품질 점검

`BASE_PROMPT`는 문서의 조건·예외, 부분적으로만 확인되는 내용, 후속 질문과 새 주제를
구분하도록 작성했다. `build_system_prompt()`는 실제 `##` 항목명으로 인용 표기를 만든다.
모델·API·패키지는 추가하지 않았으며, 일반 채팅에서 Gemini 호출은 기존처럼 한 번이다.

수정 후에는 다음 질문을 별도 대화와 연속 대화에서 확인한다.

- 월급날이 휴일인 경우 → 직전 영업일
- 자기계발비 문의 후 영수증 기한 → 결제 후 30일
- 종류 없이 영수증 기한 문의 → 비용 종류 확인
- 책값·비번 등 구어체 → 해당 규정 안내
- 명시되지 않은 자가용 km당 단가 → 금액을 만들지 않고 미기재·재무팀 확인 안내
- 개인별 잔여 연차 → 조회한 척하지 않고 실제 확인 메뉴 안내

키워드 기반이므로 등록되지 않은 표현은 추가 확인이 필요할 수 있다. 프롬프트는 모델의
오류를 완전히 막는 장치가 아니므로 중요한 숫자·조건은 원문과 함께 검토한다.
