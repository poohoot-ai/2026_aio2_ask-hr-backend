# 이 프로젝트의 API 문서화 규칙

FastAPI 프로젝트의 문서 관련 코드를 작성·수정할 때 아래 규칙을 따른다.

## 절대 지킬 것

- 함수 본문(로직)은 절대 수정하지 않는다. 데코레이터 인자와 독스트링만 추가한다.
- 엔드포인트 선언 순서를 바꾸지 않는다.
- 코드에 실제로 존재하는 동작만 문서에 적는다. 추측해서 지어내지 않는다.

## 태그

아래 4개만 사용한다. 새 태그를 만들지 않는다.

| 태그 | 대상 |
|---|---|
| 시스템 | `/`, `/health` |
| 대화 | `/conversations` 관련 |
| 인증 | `/auth` 관련 |
| 내정보 | `/me` 관련 |
| 대시보드 | `/analytics` 관련 |

## summary

- 한국어 명사형 한 줄. 예: "대화 조회"
- 문장으로 쓰지 않는다. "대화를 조회합니다" (X)

## 독스트링

- 함수 정의 바로 다음 줄에 삼중따옴표로 작성한다.
- 파라미터는 `- **이름**: 설명` 형식으로 나열한다.
- 발생 가능한 오류 상태 코드를 마지막 줄에 한 문장으로 언급한다.

## responses

- 코드에 `raise HTTPException(status_code=N, ...)` 이 실제로 있는 상태 코드만 추가한다.
- `detail` 문자열을 그대로 `description`으로 쓴다.
- `200`, `422`는 자동 생성되므로 추가하지 않는다.
- 상태 코드는 정수로 쓴다. `404` (O) / `"404"` (X)

## 모델 필드

- `description`은 한국어 명사형 짧은 구. 예: "내 대화 생성", "내 프로필 조회"
- `examples`는 실제로 있을 법한 한국어 값. `"string"`, `"abc"` 금지
- 기존 제약(`min_length`, `ge`, `le`)은 그대로 유지한다.
- 기본값이 있는 선택 필드를 `Field`로 감쌀 때는 `default=`를 반드시 명시한다.
  빠뜨리면 선택 필드가 필수로 바뀐다.
- `field_validator` 함수는 건드리지 않는다.
